Connecting a domain to the right server: DNS and NAT

AdaPanel provides tools for Windows DNS zones and records. The domain’s authoritative nameserver delegation determines which records the internet uses. A record displayed in the panel may have no public effect when another provider hosts the authoritative zone.

Where should you change the record?

Check the nameservers configured at the domain registrar first. If DNS is hosted by the registrar or another provider, edit the web record there. Windows DNS managed through AdaPanel serves as the public source only when it is authoritative for that domain.

The DNS area provides Windows DNS role installation, zone and record management. When changing nameservers, transfer mail, verification and subdomain records as well. Copying only the main A record can leave other working services behind.

Private addresses, public addresses and IPv6

Behind NAT, an IIS binding may use a private address while the public A record points to the external IPv4 address. The router must forward required traffic to the correct server. Publishing a private address in public DNS does not make a site reachable over the internet.

Publish AAAA only when the site also works over IPv6. A wrong IPv6 destination can break access for some visitors while IPv4 tests pass. Public addressing, CGNAT and provider port policies are separate from panel settings.

A practical domain transition sequence

  1. Record the existing authoritative zone and its TTL values.
  2. Prepare the new IIS hostname binding and certificate.
  3. Allow advance TTL changes to reach existing caches before switching traffic.
  4. Update A/AAAA to the intended destination; preserve unrelated MX and TXT records.
  5. Query authoritative and independent resolvers, then test the application over HTTPS at the new destination.
  6. Keep the previous server until caches and active user operations have completed the transition.

Why can the site fail when DNS is correct?

DNS identifies the destination. IIS site selection, the TLS handshake and application execution happen afterwards. For a wrong page, inspect hostname bindings; for timeouts, inspect the network path; for certificate warnings, inspect the certificate served. Clearing one computer’s cache does not refresh the whole internet.

Frequently asked questions

Must I host DNS in AdaPanel?

No. Keep DNS with your current provider and point web and mail records at the relevant servers.

Does CNAME change the address in the browser?

No. An HTTP redirect changes the browser location; a DNS alias does not perform that operation.
