Create backups and prove that recovery works

AdaPanel offers website, database, mail and panel backups with different scopes. An archive being created or a job finishing does not prove complete application recovery. Inspect the archive contents and test the restored system together.

Read what the site archive includes

An empty database selection means no database is added to the site archive. Select both files and databases for applications such as WordPress. Match file, configuration and mail options to the application’s actual dependencies.

Mail account/alias lists and message contents are distinct components. If message export tools or connectivity checks fail, the archive can contain a warning. Inspect manifest parts and mail error notes; finding account names is not proof that messages were backed up.

S3, FTP and WebDAV copies

AdaPanel supports sending a local backup to S3, FTP or WebDAV. Destination testing uploads a small file to check connectivity and write access together. Check the completed full-backup transfer separately.

A copy on the same disk is insufficient for loss of that disk or server. Plan retention, remote account access and download time. One successful destination test does not prove every historical backup is present there.

Rehearsing recovery

  1. Record the archive date, source site, included components and warnings.
  2. Prepare a separate destination without overwriting production.
  3. Restore files, configuration and selected databases onto compatible runtimes.
  4. Re-enter connection credentials and secrets that cannot be decrypted on the new machine.
  5. Test login, uploads, database writes and required mail operations.
  6. Record the actual recovery time and missing steps, then adjust the backup plan.

Limitations when moving to another computer

Panel DataProtection keys are tied to machine protection and excluded from the panel backup. Encrypted database account credentials or similar secrets may need to be entered again on a new server. Restored users and plans do not establish that every credential is usable.

A server-wide mail backup covers the whole store and involves service downtime. It is different from restoring mail for a single site. In a multi-customer environment, determine which domains an operation affects before running it.

Frequently asked questions

Does a site backup include its database by default?

Databases must be selected explicitly. A files-only archive is insufficient for a database-backed application.

No. Verify scope, warnings, remote copies and an actual restore test separately.
