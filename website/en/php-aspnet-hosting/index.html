Publishing PHP, Classic ASP and ASP.NET applications

AdaPanel provides PHP version and site settings alongside Classic ASP, ASP.NET and mixed hosting configuration. Selecting a hosting profile that matches the application is as important as copying its files to the server.

Start with the application requirements

Record the runtime version, required extensions, database engine and writable directories. For PHP, check the supported version range; for .NET, identify the target framework and deployment mode. Another working site on the same server does not establish compatibility for this application.

Set the document root to the application’s public publish directory. If a framework uses a public directory, avoid exposing the whole project root. Separate source, backups and secrets from publicly served files.

Selecting PHP versions and limits

Inspect installed PHP versions and assign a suitable version to the site. Distinguish per-site settings from server defaults: a global change can affect other applications using the same version.

Evaluate upload size, execution time and memory limits against actual requirements. Increasing PHP limits alone may not help if IIS or an upstream proxy has a lower limit. Measure the result with a real upload and application logs.

Deployment checks for ASP.NET and Classic ASP

  1. Prepare a production publish output, rather than copying only the source project.
  2. Verify the required IIS components and runtime.
  3. Select the appropriate ASP.NET, Classic ASP or mixed hosting configuration.
  4. Give the application pool read access and write access only where required.
  5. Configure production environment values and database connections securely.
  6. Test the homepage, authentication, database operations and static assets through the real HTTPS address.

Where should you start with a 500 error?

Where should you start with a 500 error?
SymptomInvestigation
Application does not startPublish output, installed runtime and startup log
Database connection failsEngine, address, account permissions and connection configuration
Uploads failApplication/PHP, IIS and proxy limits; directory permissions
Page works but routes or CSS failDocument root, static files and URL Rewrite rules

Testing a runtime upgrade

Back up application files and the database together. Test a new PHP or .NET version on a separate site and check plugins and dependencies. Retain the previous deployment package for rollback. If the application changes its database schema, copying older files back may not be a complete recovery procedure.
