Protect panel access and customer resources

AdaPanel security combines identity, sessions, network access and resource ownership. The entry path, IP allowlist, brute-force protection and two-factor authentication address different problems and should be evaluated together.

Prepare 2FA and recovery codes

Configure two-factor authentication in the account area and store recovery codes in a separate secure location. A single-use recovery code can help when the authenticator is lost. Keep codes out of shared screenshots and support messages.

Password changes can revoke existing API tokens; plan connected automations accordingly. Give people individual accounts and suitable scope instead of sharing credentials, so activity records remain meaningful.

Before applying an IP allowlist

  1. Verify the client IP the panel sees and consider NAT or proxy behavior.
  2. Prepare server-console access or another trusted management route.
  3. List required management addresses and plan for dynamic IP changes.
  4. After applying the rule, test a new session from the intended network.
  5. Verify an unapproved network is blocked and customer websites are not unexpectedly affected.
  6. Record the management change and recovery procedure.

API tokens and AI clients

An AI integration token inherits its owner’s permitted scope. Its plaintext value appears only at creation; revoke and replace a lost token. Keep it out of website content, repositories and logs.

An MCP token and the panel’s cookie-authenticated web API session are different mechanisms. Check the endpoint and authentication method used by a client. Revoke unused credentials and review access periodically.

Lockouts and incident investigation

Login lockout, subscription suspension and network blocking have different causes. Use timestamps and audit records to identify the applied control. Server-side administrator recovery procedures require authorized server access; disabling all protections is not a routine fix.

Include backups and recovery tools in the access plan. If a single person or device is the only way to manage the server, rehearse recovery from losing that access too.

Frequently asked questions

Is the hidden entry path sufficient on its own?

No. Combine it with strong authentication, HTTPS, appropriate roles and network restrictions where needed.

Can I view an API token again later?

The plaintext token is displayed only when created. Revoke and replace it if lost.
