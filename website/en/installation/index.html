AdaPanel installation guide

From Windows Server and IIS preparation to NAT, DNS and restoration testing: steps to complete before going live.

1. Prepare the server

For production, prepare Windows Server and the IIS components your application needs. Check operating system, runtime, mail and database compatibility together. On an existing server, keep a separate backup of files, databases, mail and panel settings before making changes.

2. Install the official package

Download AdaPanelSetup.exe from GitHub releases and run it as administrator. Read the release notes. If Windows asks for a restart after installing roles or features, restart the server before continuing component setup.

3. Complete initial setup locally

Initial panel setup must be completed locally on the server. Use the panel address and secure login path shown by setup. The default HTTPS port is 8888; the login path is specific to the installation. Create the administrator account and configure your chosen web, database and mail components.

4. Verify IIS and the application

PHP and phpMyAdmin cannot be published before IIS is available. If URL Rewrite reports missing IIS CoreWebEngine or W3SVC, complete IIS role installation first. Select the right runtime and test file permissions, database connections, redirects and application jobs.

5. Configure public IP, DNS and SSL

Behind NAT, keep the local IIS binding address separate from the public IP published in DNS. DNS A records must point to the reachable public IP. Verify forwarding and firewall rules for ports 80/443. Plan a reverse proxy or a separate IP if other services share those ports. Verify SSL once the domain reaches the correct destination.

6. Test restoration and external access

Restore a backup into a separate test site; verify files, databases, login and critical operations. Check that external visibility and SEO audits target the real web domain. For mail, also check MX, SPF, DKIM, DMARC, PTR and provider SMTP restrictions. Complete the DNS switch after testing.

A backup file alone is not proof of recovery. Verify the restored application works and keep the old server until the migration is complete.
